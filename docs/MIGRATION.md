## Migration approach

The first Unity 6 import compiled scripts, but reported that several original
project-settings formats were below its supported minimum. To avoid relying on
that direct conversion, an ignored `MigrationBridge/` working copy was extracted
from the original Git commit for conversion with Unity `2022.3.62f3` (`96770f904ca7`).
The original scenes, prefabs, import metadata, and settings remain recoverable
from Git history. The bridge is temporary tooling, not a second maintained game.
Conversion completed through 2022.3 to 6000.6. Scenes and assets were reserialized;
legacy project settings were saved through the intermediate editor before the
final import. Scene lighting settings generated by Unity are included with metadata.

The 2015 Google Mobile Ads integration is archived outside `Assets`; its
scene-facing MonoBehaviour keeps its original GUID as an inactive placeholder.
No ads are requested during development. Modern SDK integration remains separate.

Deprecated scene-loading calls were changed to `SceneManager`. Unity's API updater
also converted 2D rigidbody velocity access for Unity 6. The existing save system
still uses legacy BinaryFormatter data in `Application.persistentDataPath`;
modernizing save storage and validating old-save compatibility is future work.
The broken `FinishZone` prefab script reference was restored to the existing
`FinishZone.cs` (matching its `endPos` and `speed` fields). Runtime checks found
missing collectible/lock objects in per-world menus and an unassigned optional
background in Level 18; those cases now avoid null-reference exceptions.

## Repository changes and GitHub settings

Generated `Library/` state (1,255 tracked files) and the old `wormy.apk` are
removed from the Git index. Local generated files and historical copies remain.
Ignore rules cover common Unity/IDE/build output, credentials, and local tooling.
Unity YAML remains text; scenes/prefabs use the configured Smart Merge driver.
Existing small artwork stays in normal Git; future large binary source art can
use Git LFS without rewriting shared history.

GitHub settings applied and verified:

- `master`: one approving review; stale approvals dismissed.
- Require resolved conversations and an up-to-date branch.
- Require `Repository hygiene`; workflow added on the migration branch.
- Apply protections to administrators; block force pushes and branch deletion.
- Delete merged feature branches automatically; squash merging available.

The repository check runs on PRs and `master` pushes with read-only permissions.
Official Actions are pinned by commit and Dependabot checks them monthly.
This is a structural check, not licensed Unity CI. A future Unity build workflow
needs a suitable license/runner and should be introduced after migration succeeds.
